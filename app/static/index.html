WHY THIS EXISTS

More than an LLM API call

RAG Workbench answers questions from your own documents and proves each answer. It finds the right passages, checks that they support every claim, and says ‘I don’t know’ when they don’t.

What it does

  1. 1. Ingest

    Documents are split by headings into chunks and stored with embeddings and a keyword index.

  2. 2. Retrieve

    Semantic (vector) and keyword search run together and are merged with Reciprocal Rank Fusion.

  3. 3. Rerank

    A cross-encoder re-scores candidates and drops weak ones.

  4. 4. Answer and verify

    The LLM answers only from the selected chunks. Each claim is matched to the exact sentence that supports it; unsupported claims are flagged, and weak evidence triggers an abstention.

  5. 5. Measure

    A benchmark compares 4 retrieval setups on recall, ranking, answer accuracy, faithfulness, citation recall and abstention.

Why not just call an LLM API?

Capability Plain LLM API RAG Workbench
Knows your documents Only its training data, unless you paste text into the prompt Searches your indexed documents
Large document sets Limited by context window and token cost Sends only the best few chunks, so prompts stay small
Wrong but confident answers Can answer without evidence Answers only from retrieved text and abstains when evidence is weak
Sources None, or made up Every claim linked to its exact supporting sentence
Fresh information Stale after the training cutoff Upload a document and it is searchable right away, no retraining
Exact terms (IDs, config names, error codes) Often missed Keyword search catches them, vector search catches paraphrases
Quality “Seems fine” Measured with a benchmark, including unanswerable trap questions
Tuning Guesswork Settings and ablations show what actually helps

The LLM still writes the final sentence. RAG Workbench adds retrieval, verification and measurement around it.

Built with FastAPI · PostgreSQL + pgvector · tsvector · Cross-encoder reranker
